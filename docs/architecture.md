# Architecture

The Next.js App Router serves React pages and Node route handlers. Better Auth stores users, sessions, verified identity, organization membership, and email-bound invitations in PostgreSQL. Its organization plugin enforces owner/admin/member actions. Every monitoring write checks a verified session, exact application origin, a persistent per-user write rate limit, and current team membership. Owners/admins configure monitors, maintenance, and status pages; members can queue checks and collaborate on incidents. Server queries and composite foreign keys prevent linking an incident or maintenance window to another team's monitor.

Monitor checks are scheduled outside web requests. Due rows are claimed using `FOR UPDATE SKIP LOCKED`, a random lease token, and a two-minute lease. Network calls happen outside transactions; results commit only while the matching lease still belongs to the worker. Check history, state changes, and email outbox insertion share a transaction. Maintenance suppresses state-change notifications, not checks. A second lease protects outbox delivery; SMTP failure is retried after five minutes, up to five attempts. Email is at-least-once: a process crash after delivery but before recording success can cause a duplicate.

The HTTP probe accepts HTTP(S) on ports 80/443 without credentials. DNS resolution rejects every returned private/reserved address, including IPv4-mapped IPv6. The validated address is pinned into Node's connection lookup, preserving the hostname for TLS certificate validation and mitigating DNS rebinding. Redirects are not followed. Response bodies are discarded immediately, and request/DNS timeouts bound resource use. This is not a browser probe and does not execute scripts.

Public pages select only published pages and explicitly public services/incidents. They do not expose private monitor URLs, addresses, team membership, or check errors. A public incident's update text is intentionally public even when its linked monitor is private. Account deletion removes teams where the user is the sole owner; author/assignee foreign keys in shared teams are set to null.

Current scale: 20 monitors per team, 10 checks per batch, 30-day retention, 60-point charts. Sampling-based uptime should not be confused with measured duration of downtime. Scheduler leases and database state survive application restarts. The free deployment needs an external frequent scheduler; Vercel Hobby's daily cron is insufficient. A larger release should add multi-region probes, consecutive-failure policies, service-specific expected status codes, notification preferences, escalation policies, and observability for stuck/failed jobs.
